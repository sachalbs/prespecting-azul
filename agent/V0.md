# Azul v0 — ultra-simple

Le strict minimum qui prouve la valeur. Tout le reste attend.

## Le produit (v0)
**1 utilisateur (toi).** Tu donnes une liste (CSV) → Azul **trouve l'email + un
hook** (Prospeo) → **écrit un email perso** (Mistral) → **tu approuves dans le chat**
→ ça **part de ton Outlook** → il te donne le **taux de réponse**.

## Ce qu'on COUPE (volontairement)
- ❌ Holo / navigateur / scraping LinkedIn → recherche = **dossier Prospeo seul** (robuste, zéro ban)
- ❌ QR / WhatsApp → chat = **Telegram** (ou même le CLI)
- ❌ billing, paiement, multi-tenant, onboarding self-serve
- ❌ flywheel *actif* (on **enregistre** les outcomes, on n'agit pas encore dessus)
- ❌ relances auto (optionnel)

## Ce qu'on GARDE (la chaîne de valeur)
`Prospeo (email + dossier) → hook → Mistral (message) → toi (1 tap) → Outlook (envoi) → rapport`

## Config `.env` v0
```
SOURCING_PROVIDER=prospeo
RESEARCH_ENGINE=dossier         # Prospeo seul, pas de navigateur
WRITER_PROVIDER=openai_compat   # Mistral
CHANNEL=graph                   # Outlook
PROSPEO_API_KEY=…  WRITER_BASE_URL=https://api.mistral.ai/v1  WRITER_MODEL=mistral-large-latest  WRITER_API_KEY=…  GRAPH_CLIENT_ID=…
```

## Lancer (sur une machine avec internet : ton ordi ou un petit worker)
```
uv run azul init-db
uv run azul auth-email          # connecte ton Outlook (1 fois)
uv run azul chat                # ou: azul telegram-bot
# puis: campaign Q1 from liste.csv / show / approve all / send / report
```

## Ce qu'il reste à faire (presque rien — c'est de l'ops, pas du dev)
1. Mettre tes clés dans `.env` + `azul auth-email`.
2. Le faire tourner sur une machine ouverte sur internet (ton ordi suffit).
3. → **le premier vrai taux de réponse.** C'est ça qui décide de la suite.
